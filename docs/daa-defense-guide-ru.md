# Подготовка к защите DAA Assignment 1

Этот материал объясняет Java-решения пяти задач DAA Assignment 1: количество вхождений, медиана двух массивов, максимальная сумма участка, ближайшая пара точек и умножение больших чисел. Для каждой задачи разобраны оба метода, примеры, доказательство правильности и сложность.

На защите нужно уметь объяснить четыре вещи: **что ищем, как работает алгоритм, почему ответ правильный и сколько ресурсов требуется**.

## Общая идея задания

У каждой задачи два решения:

- **Brute** — прямой способ: просмотреть элементы, перебрать участки или пары, перемножить все цифры.
- **Smart** — использовать структуру задачи, чтобы выполнить меньше работы.

«Разделяй и властвуй» обычно означает: разделить задачу, решить меньшие задачи и объединить результаты. В бинарном поиске продолжаем работу только с одной половиной.

`n` обычно обозначает количество элементов. В задаче умножения — количество **цифр**, а не величину числа.

## Задача 1 Number of Occurrences

Дан **отсортированный массив** и `key`. Нужно вернуть количество его вхождений.

```text
Индексы:  0  1  2  3  4
Массив:  [1, 2, 2, 2, 4]

key = 2
Ответ = 3
```

### Прямой подсчёт

`countFreqBrute()` создаёт счётчик `count = 0`, проходит по массиву и увеличивает его при совпадении:

```java
if (A[i] == key) {
    count++;
}
```

После цикла метод возвращает `count`.

Почему это правильно: каждый элемент проверяется один раз, каждое совпадение добавляет ровно единицу.

Если совпадений нет, счётчик остаётся нулём. Для пустого массива цикл не выполняется — ответ тоже `0`.

**Сложность:** Θ(n) времени и O(1) дополнительной памяти.

### Два бинарных поиска

Главное наблюдение: **в отсортированном массиве одинаковые числа стоят подряд**.

`countFreqSmart()` находит:

- `first` — индекс первого вхождения;
- `last` — индекс последнего вхождения.

Ответ:

```java
return last - first + 1;
```

В примере: `3 - 1 + 1 = 3`. Единица нужна, потому что обе границы включены.

| Переменная | Значение |
|---|---|
| `low` | Левая граница текущего поиска |
| `high` | Правая граница |
| `mid` | Середина |
| `first`, `last` | Лучший найденный индекс соответствующей границы |

При поиске первого вхождения:

```java
if (A[mid] == key) {
    first = mid;
    high = mid - 1;
}
```

Подходящий элемент найден, но слева может быть ещё один такой же. Поэтому запоминаем индекс и продолжаем слева.

При поиске последнего:

```java
if (A[mid] == key) {
    last = mid;
    low = mid + 1;
}
```

Теперь продолжаем справа.

В обоих поисках:

- если `A[mid] < key`, слева ответа быть не может — идём вправо;
- если `A[mid] > key`, справа ответа быть не может — идём влево.

Если после первого поиска `first == -1`, ключ отсутствует и метод возвращает `0`.

`-1` — внутреннее обозначение «индекс не найден». Количество вхождений при отсутствии числа — **0**.

### Сложность бинарного поиска

Каждый шаг примерно вдвое уменьшает область поиска:

```text
16 → 8 → 4 → 2 → 1
```

Два поиска дают O(log n) + O(log n) = O(log n). Они выполняются циклами, поэтому дополнительная память — O(1).

### Что важно объяснить на защите

- Без сортировки бинарный поиск не работает: сравнение с серединой не позволяет отбросить половину.
- Обычный бинарный поиск находит какое-нибудь вхождение. Для поиска границы нельзя останавливаться сразу после совпадения.
- Формула `low + (high - low) / 2` позволяет избежать возможного переполнения суммы `low + high`.

## Задача 2 Median of Two Sorted Arrays

Нужно представить элементы двух массивов как одну отсортированную последовательность и найти её середину.

```text
A = [2, 4]
B = [3, 5]

Общий порядок: [2, 3, 4, 5]
Медиана: (3 + 4) / 2 = 3.5
```

**Медиана не является средним всех элементов.** Это центральный элемент или среднее двух центральных.

### Слияние массивов

`getMedianBrute()` сливает уже отсортированные массивы.

Используются три индекса:

- `i` — текущий элемент `A`;
- `j` — текущий элемент `B`;
- `k` — место для записи в `merged`.

Сравниваем `A[i]` и `B[j]`, записываем меньший и сдвигаем соответствующий указатель.

```text
A = [2, 4], B = [3, 5]

2 < 3 → берём 2
4 > 3 → берём 3
4 < 5 → берём 4
A закончился → дописываем 5
```

Оставшиеся два цикла дописывают остаток массива, который ещё не закончился.

Затем:

- нечётная длина — `merged[total / 2]`;
- чётная длина — среднее элементов на позициях `total / 2 - 1` и `total / 2`.

Почему правильно: на каждом шаге выбирается наименьший из оставшихся элементов, поэтому результат остаётся отсортированным.

**Сложность:** Θ(n + m) времени и Θ(n + m) памяти для `merged`.

### Бинарный поиск разделения

`getMedianSmart()` не строит общий массив. Нужно найти разделение:

```text
ЛЕВАЯ ЧАСТЬ | ПРАВАЯ ЧАСТЬ
```

Чтобы:

1. слева находилась половина элементов — с одним дополнительным элементом при нечётной общей длине;
2. каждый элемент слева был не больше любого элемента справа.

Если разделение найдено, медиана находится возле его границы.

`cutA` — **количество элементов A, взятых влево**. Аналогично `cutB`.

```java
int leftSize = (n + m + 1) / 2;
int cutB = leftSize - cutA;
```

Выбрав `cutA`, автоматически получаем `cutB`.

```text
A = [2 | 4]
B = [3 | 5]

Общая левая часть:  [2, 3]
Общая правая часть: [4, 5]

leftA = 2       rightA = 4
leftB = 3       rightB = 5
```

Проверяем:

```java
leftA <= rightB && leftB <= rightA
```

То есть `2 <= 5` и `3 <= 4`.

Внутри каждого массива порядок уже правильный. Эти два сравнения проверяют порядок между массивами.

Для чётной длины:

```java
leftMax = Math.max(leftA, leftB);    // 3
rightMin = Math.min(rightA, rightB); // 4
```

Ответ: `(3 + 4) / 2.0 = 3.5`.

Для нечётной длины левая часть содержит один лишний элемент. Он является медианой — это `leftMax`.

### Как двигается поиск

Если `leftA > rightB`, из `A` взяли влево слишком много элементов. Уменьшаем `cutA`.

Иначе при неправильном разделении выполняется `leftB > rightA`: из `A` взяли слишком мало элементов. Увеличиваем `cutA`.

Пример:

```text
A = [1 | 2]
B = [3 | 4]
```

Здесь `leftB = 3 > rightA = 2`. Передвигаем границу в `A` вправо:

```text
A = [1, 2 | ]
B = [     | 3, 4]
```

Теперь разделение правильное, медиана — `2.5`.

### Границы массивов и сложность

Если слева или справа нет элемента, код подставляет условные границы:

- для пустой левой части — `Integer.MIN_VALUE`;
- для пустой правой части — `Integer.MAX_VALUE`.

Это позволяет использовать одинаковые сравнения даже на краях массива.

Поиск выполняется по короткому массиву: так меньше область поиска, а количество элементов из второго массива остаётся допустимым.

**Сложность:** O(log(s + 1)), где s = min(n, m) для непустого короткого массива. Если один массив пуст — O(1). Дополнительная память — O(1).

### Что важно объяснить на защите

- `+1` в `(n + m + 1) / 2` отдаёт лишний элемент левой части при нечётной длине.
- Приведение к `double` перед сложением предотвращает переполнение целочисленной суммы, а `/ 2.0` сохраняет дробную часть.
- Полностью сортировать данные не требуется: оба массива уже отсортированы.
- Два пустых массива запрещены условием.

## Задача 3 Largest Subrange

Нужно выбрать **непустой непрерывный участок** с максимальной суммой.

```text
A = [-2, 3, -1, 4, -5]

Лучший участок: [3, -1, 4]
Сумма: 6
```

Нельзя просто выбрать все положительные числа: элементы участка должны идти подряд.

### Перебор всех участков

В `maxSumBrute()` внешний цикл выбирает начало `i`, а внутренний постепенно двигает конец `j`.

```java
currentSum += A[j];
```

Для начала на элементе `3`:

```text
[3]              → 3
[3, -1]          → 2
[3, -1, 4]       → 6
[3, -1, 4, -5]   → 1
```

Сумма обновляется добавлением одного элемента. Каждый участок не пересчитывается заново.

Всего участков:

```text
n + (n - 1) + ... + 1 = n(n + 1) / 2
```

Поэтому время — Θ(n²), память — O(1). Если бы сумму каждого участка вычисляли отдельным третьим циклом, получилось бы O(n³).

Максимум начинается с `Integer.MIN_VALUE`, чтобы правильно обработать отрицательные числа:

```text
[-5, -2, -7] → ответ -2
```

При начальном максимуме `0` программа могла бы ошибочно вернуть `0`, хотя такого непустого участка нет.

### Разделение на три случая

`maxSumSmart()` разделяет массив пополам:

```text
[-2, 3, -1 | 4, -5]
```

Ответ может находиться только в одном из трёх положений:

1. полностью слева;
2. полностью справа;
3. пересекать середину.

Первые два результата находятся рекурсивно:

```java
int bestLeft = solve(A, left, middle);
int bestRight = solve(A, middle + 1, right);
```

Для примера `bestLeft = 3`, `bestRight = 4`.

### Поиск пересекающего участка

Он состоит из:

- некоторого окончания левой половины — **суффикса**;
- некоторого начала правой половины — **префикса**.

Слева идём от середины назад:

```text
[-1]        → -1
[3, -1]     →  2
[-2, 3, -1] →  0

Лучший суффикс: 2
```

Справа идём от середины вперёд:

```text
[4]     →  4
[4, -5] → -1

Лучший префикс: 4
```

Пересекающий ответ: `2 + 4 = 6`.

Итог:

```java
Math.max(Math.max(bestLeft, bestRight), bestCrossing)
```

Максимум из `3`, `4`, `6` равен `6`.

Нельзя просто сложить `bestLeft + bestRight`: лучший участок слева может закончиться далеко от середины, а лучший справа — начаться далеко от неё. Между ними получится пропуск. Нужны именно суффикс и префикс, прилегающие к границе.

### База рекурсии и сложность

Когда `left == right`, остаётся один элемент. Лучший непустой участок состоит из него самого.

Две подзадачи половинного размера и линейный проход для пересекающего участка дают:

```text
T(n) = 2T(n/2) + Θ(n) = Θ(n log n)
```

Память — O(log n) для стека. Массив не копируется: передаются его границы. По ограничениям сумма по модулю не превышает 10^9, поэтому `int` достаточен.

Если спросят о более быстром решении, существует алгоритм Кадане за O(n). Рассматриваемое решение демонстрирует требуемое рекурсивное разделение задачи.

## Задача 4 Closest Pair

Даны точки `[x, y]`. Нужно вернуть минимальное расстояние между двумя разными элементами массива.

Евклидово расстояние:

```text
d = sqrt((x1 - x2)^2 + (y1 - y2)^2)
```

Для `(0, 0)` и `(3, 4)` расстояние равно `5`.

### Перебор всех пар

`minDistBrute()` перебирает все пары:

```java
for (int i = 0; i < n; i++) {
    for (int j = i + 1; j < n; j++) {
        // Вычисление расстояния и обновление минимума.
    }
}
```

`j` начинается с `i + 1`, чтобы не сравнивать точку с самой собой и не проверять одну пару дважды.

Число пар равно n(n - 1) / 2. **Сложность:** Θ(n²) времени и O(1) дополнительной памяти.

В `dist()` используется:

```java
Math.hypot(dx, dy)
```

Этот метод избегает проблем промежуточного возведения в квадрат. Например, квадрат `10^200` переполнит `double`, хотя само расстояние `10^200` представимо.

### Разделение точек и проверка границы

`minDistSmart()` сначала копирует точки, чтобы сортировка не меняла входной массив, и сортирует их по `x`.

Далее рекурсивно делит точки на левую и правую группы, находит `dLeft`, `dRight` и выбирает `d = min(dLeft, dRight)`.

Этого недостаточно: ближайшая пара может состоять из точки слева и точки справа.

Пример точек на оси x:

```text
0    4 | 5    9
```

В каждой половине минимальное расстояние равно `4`, но между точками `4` и `5` расстояние равно `1`.

### Полоса возле границы

Если уже найдено расстояние `d`, интересны только пары, расположенные ещё ближе.

Для пары из разных половин обе точки должны находиться на горизонтальном расстоянии меньше `d` от разделяющей линии. Поэтому в `tempStrip` попадают точки, удовлетворяющие:

```java
Math.abs(x - midX) < d
```

В рассматриваемом коде модуль вычисляется вручную через проверку знака.

Точки далеко от границы не могут образовать более короткую пару с противоположной половиной.

### Сортировка полосы по y

После сортировки следующие точки просматриваются снизу вверх.

Как только:

```java
tempStrip[j][1] - tempStrip[i][1] >= d
```

проверять дальнейшие точки для данного `i` бессмысленно. Разница только по вертикали уже не меньше лучшего расстояния, а дальше она лишь увеличится.

Два цикла здесь не означают полный квадратичный перебор. В каждой половине расстояния между точками уже не меньше найденного `d`. Поэтому в маленькой области возле текущей точки нельзя разместить произвольно много близких соседей.

Геометрическое доказательство ограничивает число нужных соседей константой — в стандартном разборе достаточно следующих семи. Код не задаёт число `7` явно: он останавливается по разнице `y`.

### База рекурсии и сложность

Условие:

```java
if (right - left <= 2)
```

означает **не более трёх точек**, поскольку обе границы включены:

```text
число точек = right - left + 1
```

Для них выполняется прямой перебор.

В каждом вызове полоса сортируется заново:

```text
T(n) = 2T(n/2) + O(n log n)
```

Итог — **O(n log² n)**. Это точная для защиты верхняя оценка рассматриваемой версии. Более сложная версия с поддержанием порядка по y может работать за O(n log n).

Дополнительная память — O(n), глубина рекурсии — O(log n).

### Граничные случаи

- Совпадающие точки дают расстояние `0`.
- Для одной точки возвращается `Double.POSITIVE_INFINITY`: пары нет. Это принятое соглашение, поскольку условие не задаёт ответ.
- Точки с одинаковой координатой `x` допустимы: разделение происходит по индексам отсортированного массива.

## Задача 5 Integer Multiplication

Числа передаются строками, потому что могут содержать до **10 000 цифр**. Тип `long` такое число не вместит. Нужно самостоятельно работать с цифрами.

```text
A = "23"
B = "14"

Ответ = "322"
```

### Умножение в столбик

`multBrute()` выполняет обычное умножение в столбик:

```text
   23
×  14
-----
   92
  230
-----
  322
```

Каждая цифра первого числа умножается на каждую цифру второго.

Чтобы превратить символ в число:

```java
int d1 = A.charAt(i) - '0';
```

Например, `'7' - '0'` даёт `7`.

Результат хранится в массиве:

```java
int[] res = new int[n + m];
```

Произведение n-значного и m-значного чисел содержит не больше n + m цифр.

Циклы идут справа налево — от младших разрядов к старшим.

```java
int sum = d1 * d2 + res[i + j + 1];

res[i + j + 1] = sum % 10;
res[i + j] += sum / 10;
```

- `sum % 10` — цифра текущего разряда;
- `sum / 10` — перенос в следующий разряд слева;
- `res[i + j + 1]` учитывает результаты, уже накопленные в этой позиции.

Если `sum = 17`, записываем `7`, а `1` переносим влево.

После умножений массив превращается в строку. Ведущие нули пропускаются. Если весь результат нулевой, возвращается `"0"`.

**Сложность:** Θ(nm) в худшем случае, память — O(n + m). При одинаковых длинах получается Θ(n²).

### Алгоритм Карацубы

`multSmart()` разделяет каждое число на две части:

```text
A = a × 10^k + b
B = c × 10^k + d
```

Например:

```text
A = 1234 → a = 12, b = 34
B = 5678 → c = 56, d = 78
k = 2
```

При раскрытии скобок:

```text
AB = ac × 10^(2k) + (ad + bc) × 10^k + bd
```

Нужны четыре произведения: `ac`, `ad`, `bc`, `bd`.

Карацуба получает результат с помощью **трёх**:

```text
p1 = ac
p2 = bd
p3 = (a + b)(c + d)
```

Поскольку:

```text
(a + b)(c + d) = ac + ad + bc + bd
```

получаем:

```text
ad + bc = p3 - p1 - p2
```

Это делает строка:

```java
String midTerm = subtract(subtract(p3, p1), p2);
```

### Пример Карацубы

Для `1234 × 5678`:

```text
p1 = 12 × 56 = 672
p2 = 34 × 78 = 2652
p3 = 46 × 134 = 6164

midTerm = 6164 - 672 - 2652 = 2840
```

Собираем:

```text
672 × 10000 + 2840 × 100 + 2652
= 6 720 000 + 284 000 + 2 652
= 7 006 652
```

Это пример формулы. Для таких коротких чисел код сразу использует умножение в столбик: рекурсия нужна для более длинных операндов.

### Вспомогательные методы

| Метод | Назначение |
|---|---|
| `trimLeadingZeros()` | Удаляет нули слева, сохраняя один ноль для числа 0 |
| `padLeft()` | Дополняет число нулями слева до нужной длины |
| `add()` | Складывает строки по цифрам с переносом |
| `subtract()` | Вычитает по цифрам с заимствованием; требует первое число ≥ второго |
| `shiftLeft()` | Дописывает нули справа, то есть умножает на степень десяти |

`shiftLeft()` здесь делает **десятичный сдвиг**, а не побитовый сдвиг Java.

```text
padLeft("123", 5)   → "00123" — значение не меняется
shiftLeft("123", 2) → "12300" — значение умножается на 100
```

В `add()` и `subtract()` цифры обрабатываются справа налево. Они добавляются в обратном порядке, поэтому в конце используется `reverse()`.

Вычитания в формуле не дают отрицательного числа:

```text
p3 - p1 = ad + bc + bd ≥ bd
```

После вычитания `p2 = bd` остаётся неотрицательное `ad + bc`.

### Завершение рекурсии и сложность

В начале удаляются ведущие нули. Если один операнд нулевой, возвращается `"0"`.

Если хотя бы один операнд содержит не более 32 значащих цифр:

```java
return multBrute(A, B);
```

Иначе числа дополняются до одинаковой **чётной** длины и делятся пополам. Сумма половин может иметь дополнительную цифру, но размер подзадач уменьшается до базового случая.

Порог `32` — практический выбор для уменьшения накладных расходов, а не обязательное число из математики Карацубы.

Три произведения примерно половинной длины и линейная работа со строками дают:

```text
T(n) = 3T(n/2) + O(n)
T(n) = O(n^(log₂3)) ≈ O(n^1.585)
```

Память — O(n) для одновременно необходимых строк и массивов; глубина рекурсии — O(log n).

### Что важно объяснить на защите

- Главный выигрыш Карацубы — замена четырёх рекурсивных умножений тремя.
- Сложение и вычитание больших чисел линейны по числу цифр.
- `BigInteger` используется только в `main()` для проверки, как разрешено условием.
- Реализация принимает неотрицательные числа без знака и поддерживает ведущие нули.

## Объяснение сложности через Master method

Общий вид:

```text
T(n) = aT(n/b) + f(n)
```

- `a` — сколько рекурсивных подзадач;
- `b` — во сколько раз уменьшается размер;
- `f(n)` — работа вне рекурсивных вызовов.

| Алгоритм | Соотношение | Результат |
|---|---|---|
| Бинарный поиск | T(n) = T(n/2) + O(1) | O(log n) |
| Максимальная сумма | T(n) = 2T(n/2) + Θ(n) | Θ(n log n) |
| Ближайшая пара в этой версии | T(n) ≤ 2T(n/2) + O(n log n) | O(n log² n) |
| Карацуба | T(n) = 3T(n/2) + O(n) | O(n^1.585) |

В задаче 3 на каждом уровне рекурсии суммарно обрабатывается около n элементов, а уровней около log n. Отсюда n log n.

В задаче 4 повторная сортировка добавляет ещё один логарифмический множитель.

В Карацубе log₂3 ≈ 1.585, и рекурсивная часть растёт быстрее линейной работы со строками.

**O обозначает верхнюю оценку роста, а Θ — точный асимптотический порядок.** Они не показывают время в секундах.
